# Загрузка программы из UI

Из корня репозитория запустите:

```bash
docker compose up --build
```

Откройте http://localhost:9055, выберите `copy.mlir` и `inputs.npz`
из этой директории, затем нажмите «Проверить файлы».
Для `copy_kernel` свяжите аргумент 0 с `source`, аргумент 1 — с заполнением
нулями и нажмите «Выполнить». Обновление страницы восстанавливает состояние.

Пример содержит приватную функцию копирования матрицы 4×4 f32. NPZ можно
подготовить самостоятельно:

```python
import numpy as np
np.savez("inputs.npz", source=np.arange(16, dtype=np.float32).reshape(4, 4))
```

При L1 размером 128 B, строке 64 B, 2 ways и LRU результат — 32 обращения,
30 попаданий, 2 промаха, hit rate 93.75%. При неизменном входе это проверяемый
пример, а не оценка производительности реального CPU.

По умолчанию запуск не ограничен временем и числом событий. Эти ограничения
можно задать в форме; незавершённая или усечённая трасса не превращается в
итоговый отчёт. «Отменить» завершает worker и все его дочерние процессы.

Функция должна иметь только статические identity-layout memref<f32>
аргументы и не возвращать значений. Для каждого аргумента выбирается отдельный
буфер из NPZ или нулевое заполнение. Tensor-аргументы, динамические формы,
другие типы, вызовы других функций и возвращаемые значения пока не поддержаны.

Docker использует закреплённый LLVM проекта на Ubuntu 24.04 amd64; на Mac с
Apple Silicon он запускается через эмуляцию. Сборка скачивает зависимости,
а при старте готового образа компиляция приложения или npm install не нужны.
В контейнер не монтируется файловая система хоста. Один текущий эксперимент
хранится до замены или остановки backend, без истории и экспорта.

API и инструкции проверки: [EXPERIMENT_API.md](../../docs/EXPERIMENT_API.md).
