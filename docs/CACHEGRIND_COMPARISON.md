# Сравнение с Valgrind Cachegrind

`scripts/compare_cachegrind.py` сравнивает L1D CacheScope и Cachegrind на
небольших нативных C kernels с однобайтовыми обращениями. Проверенный запуск:
Valgrind 3.22.0, GCC 13.3.0, Ubuntu 24.04 AArch64; совпали все 25 префиксов
трёх последовательностей. Скрипт требует Valgrind с поддержкой
`--instr-at-start=no`, client requests Cachegrind и заголовком `valgrind/cachegrind.h`.

## Запуск

```sh
python3 scripts/compare_cachegrind.py --output /tmp/cachescope-cachegrind-results
```

Нужны `valgrind`, C и C++17 компиляторы и заголовки Valgrind. Выходной каталог
должен отсутствовать. Дополнительные параметры: `--valgrind` задаёт исполняемый
файл, `--include` — каталог, содержащий `valgrind/cachegrind.h`, `--cc` и
`--cxx` выбирают компиляторы. Если Valgrind распакован без установки, может
потребоваться задать `VALGRIND_LIB` в окружении.

В выходном каталоге сохраняются исходники kernels для каждого префикса,
Cachegrind output и log, фактические абсолютные адреса обращений для CacheScope,
а также `summary.json` с версиями, хешами исходников и счётчиками. При ошибке
скрипт возвращает ненулевой код, сохраняя созданные артефакты.

## Методика

1. Для каждого префикса скрипт генерирует отдельный kernel с явно заданными
   volatile read/write и запускает его в новом процессе Cachegrind. Результаты
   чтений используются, чтобы они не удалялись при обработке машинного кода.
2. Инструментация выключена на старте и включается client request перед kernel;
   итоговые метрики выбираются только для строк функции `kernel`. Скрипт
   проверяет, что на каждой строке учтено ровно одно ожидаемое чтение или запись
   и что в остальных строках kernel нет обращений к данным.
3. Kernel сообщает фактический адрес массива после выключения инструментации.
   Выравнивание массива проверяется; этот адрес и те же смещения передаются
   вспомогательной программе, которая вызывает `CacheHierarchy` напрямую.
4. Обе модели используют D1 32 KiB, 8 ways, строки по 64 байта и LRU. Скрипт
   сравнивает `Dr`, `D1mr`, `Dw`, `D1mw` после каждого префикса. Финальные
   результаты дополнительно проверяются по вручную рассчитанным значениям.

Трассы покрывают повторные чтения, write-allocate и конфликт девяти строк в
одном set. Работа client requests и caller может обращаться к памяти до kernel;
они не входят в счётчики kernel, но могут влиять на его начальное cache state.
При возникающем из-за этого различии проверка завершается ошибкой — считать его
ошибкой симулятора без дополнительного анализа нельзя.

Сравниваются только указанные однобайтовые операции в kernel и L1D. Доступы
через границу строки и read-modify-write исключены: Cachegrind считает их иначе.
Это сравнение не проверяет trace producer, runner, модели нижних уровней,
dirty writeback или поведение реального процессора. Семантика Cachegrind описана
в [его руководстве](https://valgrind.org/docs/manual/cg-manual.html).

## GitHub Actions

Workflow `.github/workflows/cachegrind.yml` запускает сравнение на
`ubuntu-24.04-arm` при push, pull request и вручную. Он устанавливает Valgrind
и компиляторы из репозитория Ubuntu 24.04; версия Valgrind сохраняется в
`summary.json`. Ошибка компиляции, запуска или расхождение счётчиков приводит
к ошибке проверки. Созданные к этому моменту отчёты публикуются артефактом
`cachegrind-comparison` и хранятся семь дней.
