# Сравнение с DynamoRIO drcachesim

Скрипт `scripts/compare_drcachesim.py` воспроизводит короткие синтетические
трассы непосредственно через CacheScope и drcachesim. Он сравнивает накопленные
hits и misses после каждого префикса: для каждого префикса drcachesim запускается
заново с пустым кешем. Так определяется исход каждого обращения без зависимости
от совпадения только итоговых сумм.

## Запуск

Нужны Python 3, C++17 compiler и установленный или распакованный DynamoRIO с
`tools/bin64/drmemtrace_launcher` и его динамическими библиотеками. Скрипт
проверен с **DynamoRIO AArch64 Linux 11.91.20763**, Ubuntu 24.04 и GCC 13.3.0.
Пакет DynamoRIO и его зависимости не входят в репозиторий.

```sh
python3 scripts/compare_drcachesim.py \
  --dynamorio /path/to/DynamoRIO \
  --output /tmp/cachescope-drcachesim-results
```

Выходной каталог должен отсутствовать. Если системный загрузчик не находит
зависимости DynamoRIO, перед запуском настройте `LD_LIBRARY_PATH` для своей
системы. Выбрать компилятор можно через `--cxx` или переменную `CXX`.
Сборка replay-программы происходит во временном каталоге.

В выходном каталоге остаются исходные обращения, бинарная трасса и полный вывод
drcachesim для каждого префикса, вывод CacheScope и `summary.json` с командами,
хешем launcher, версией компилятора, конфигурацией и счётчиками. При ошибке
скрипт возвращает ненулевой код и оставляет уже записанные файлы для диагностики.

## Что сравнивается

- Один поток, пустое начальное состояние; L1D 128 байт, 64 байта на строку,
  два way в одном set, LRU, prefetcher выключен.
- Три набора однобайтовых read/write с повторениями, конфликтами и
  write-allocate. Обращения не пересекают границу строки.
- Оба симулятора получают одинаковые абсолютные адреса и порядок обращений.
  CacheScope запускается через API `CacheHierarchy`, а не через trace runner.
- drcachesim получает синтетические записи формата `trace_entry_t` версии 8;
  фиктивные instruction records нужны для формата и обрабатываются отдельным
  L1I. Он также моделирует LL, но сравниваются только локальные L1D hit/miss.
- Каждый запуск проверяет, что drcachesim сообщил ожидаемые параметры L1D и что
  число hits плюс misses равно длине префикса для обеих систем.

Проверенный запуск: все 19 префиксов трёх трасс совпали. Это подтверждает
результаты только для перечисленных условий и не проверяет dirty writeback,
многоуровневую exclusive-иерархию, генератор semantic trace или поведение
реального процессора. Формат синтетической трассы и интерпретация отчёта могут
зависеть от версии DynamoRIO; другая версия должна пройти эту же проверку.

Документация DynamoRIO: [формат трасс](https://dynamorio.org/sec_drcachesim_format.html),
[параметры симулятора](https://dynamorio.org/sec_drcachesim_ops.html).

## Двухуровневая exclusive-иерархия

Отдельный запуск сравнивает demand hits и misses на L1D и L2 после каждого
префикса. Для обеих моделей L1D и L2 имеют 128 байт, две ways, размер строки
64 байта и LRU. L2 настроен как `exclusive`, prefetch отключён. L1I в
конфигурации drcachesim подключён напрямую к памяти, чтобы instruction records
не меняли состояние L2 данных. Префиксы запускаются с пустым кешем.

```sh
python3 scripts/compare_drcachesim_exclusive.py \
  --dynamorio /path/to/DynamoRIO \
  --output /tmp/cachescope-drcachesim-exclusive-results
```

Скрипт сохраняет фактическую конфигурацию, обращения, сырые отчёты, команды и
сводку. Три трассы проверяют попадание в L2 с продвижением в L1, запись и
переносы строк, а также 32 воспроизводимых обращения с seed `0x12345678`.
Для короткой трассы продвижения дополнительно проверяются вручную рассчитанные
счётчики каждого префикса. Проверенный запуск на DynamoRIO 11.91.20763: все
45 префиксов совпали для обоих уровней.

Сравнение ограничено однопоточными однобайтовыми обращениями и указанной
геометрией. В отчёте drcachesim этой конфигурации нет счётчика, сопоставленного
с dirty writeback CacheScope: записи включены в трассы, но сохранение dirty и
writeback здесь не подтверждаются. Трёхуровневая иерархия, runner и semantic
trace также не входят в это сравнение.

## Трёхуровневая exclusive-иерархия

Скрипт добавляет L3 к предыдущей конфигурации: каждый уровень данных имеет
128 байт, две ways и строки по 64 байта, LRU; L2 и L3 — exclusive. L1I
подключён напрямую к памяти. Сравниваются локальные demand hits/misses L1D,
L2 и L3 после каждого префикса из пустого состояния.

```sh
python3 scripts/compare_drcachesim_three_levels.py \
  --dynamorio /path/to/DynamoRIO \
  --output /tmp/cachescope-drcachesim-three-results
```

Три трассы содержат вручную рассчитанное попадание в L3 с каскадным
вытеснением, обращения с записями и 32 обращения с фиксированным seed. В
проверенном запуске DynamoRIO 11.91.20763 совпали все 49 префиксов;
сгенерированная трасса содержит попадания во все три уровня. Скрипт сохраняет
те же артефакты, что и двухуровневое сравнение. Эта проверка не сравнивает
состояние dirty или writeback и не проверяет trace producer либо runner.
