# CacheScope UI

Веб-интерфейс для просмотра и сравнения результатов моделирования кэш-памяти в проекте CacheScope.

UI состоит из двух частей:

- **Статистика** — загрузка готовых экспериментов, просмотр метрик кэша и сравнение вариантов программы. Результат можно сохранить в автономный HTML-отчёт.
- **Пошаговая симуляция** — выполнение trace по одному событию с просмотром физического состояния кэша. Доступна только в режиме разработки и требует запущенного backend (runner).

## Возможности

- **Загрузка экспериментов** — импорт директории с результатами через выбор папки в браузере.
- **Общая статистика** — количество обращений к линиям кэша, попадания (`hits`), промахи (`misses`), вытеснения (`evictions`) и обратные записи (`writebacks`), в том числе отдельно для чтения и записи.
- **Hit rate и miss rate** — доли попаданий и промахов, рассчитанные отдельно для каждого уровня кэша.
- **Иерархия кэшей** — переключение между уровнями (L1, L2 и другими, если они есть в данных), политики иерархии и статистика обращений к памяти.
- **Сравнение вариантов** — таблица с дельтами hit rate и числа промахов относительно базового варианта (`baseline`, а если его нет — первого в списке). Варианты группируются по одинаковой конфигурации кэша и иерархии.
- **Поинструкционная статистика** — результаты для отдельных обращений к памяти (`access_id`), если в данных есть поле `instructions`.
- **Проверка согласованности** — предупреждения о противоречиях в счётчиках, о расхождении `cache_config` и `levels`, а также о проблемах с trace: он усечён, помечен невалидным или число событий не совпадает с числом, обработанным симулятором.
- **Автономные HTML-отчёты** — один HTML-файл с интерфейсом и данными эксперимента; открывается без сервера.
- **Пошаговая симуляция** — по шагам: текущее событие, результаты по уровням, вытеснения, MLIR-исходник с подсветкой позиции, физическое состояние sets/ways, тепловая карта sets, лента hit/miss по шагам, накопленная статистика и журнал запросов к backend.

## Входные данные

UI работает с результатами, подготовленными другими компонентами CacheScope. Он не запускает компиляцию и не выполняет симуляцию кэша самостоятельно.

Ожидаемая структура директории эксперимента:

```text
output/<experiment>/
├── baseline/
│   └── trace.json
├── tile4/
│   └── trace.json
├── tile4-ikj/
│   └── trace.json
└── simulation/
    ├── baseline-l1/
    │   └── statistics.json
    ├── tile4-l1/
    │   └── statistics.json
    └── tile4-ikj-l1/
        └── statistics.json
```

Названия вариантов приведены для примера. UI ищет файлы по шаблонам `simulation/*/statistics.json` и `<variant>/trace.json`, а trace сопоставляет со статистикой по полю `variant`. Другие файлы в директории (`summary.json`, `events.json` и т. п.) UI не читает.

Источники данных:

- `statistics.json` — результаты симуляции, сформированные cache emulator. Обязателен: без него нечего показывать.
- `trace.json` — trace, сформированный compiler trace producer. Необязателен: UI читает только заголовок (`total_events`, `recorded_events`, `truncated`) и использует его для проверки полноты данных. Без trace статистика всё равно отображается.

Поддерживаемые схемы:

- `cachescope.trace.v1`;
- `cachescope.simulation-statistics.v1`.

UI проверяет файлы на соответствие схемам. Недоступные необязательные данные отображаются как «—», а не как нули. Файлы, не прошедшие проверку, перечисляются в блоке «Ошибки чтения».

## Запуск в режиме разработки

Требуется Node.js `^20.19.0` или `>=22.12.0` и npm.

```bash
cd ui
npm ci
npm run dev
```

Vite выведет адрес локального сервера в терминале. Откройте его и выберите папку эксперимента (`output/<experiment>/`).

## Пошаговая симуляция

Страница доступна по адресу `/?view=stepper` (ссылка «Пошаговая симуляция →» есть в заголовке основной страницы).

Для работы нужен backend (runner) с HTTP API. Адрес по умолчанию — `http://127.0.0.1:9055/api/v1`, его можно изменить в форме новой сессии.

1. Укажите абсолютный путь к `trace.json` — вручную, через кнопку «Обзор…» или из списка недавних trace. Файл не загружается через браузер: backend открывает его по этому пути.
2. Задайте конфигурацию кэша: для каждого уровня — имя, размер, размер линии, associativity и политику вытеснения (`LRU`, `FIFO`, `Random`). Размер линии должен быть одинаковым на всех уровнях, а число sets (`size / (line_size × associativity)`) — степенью двойки.
3. Нажмите «Создать сессию» и выполняйте шаги: «Следующий шаг» выполняет одно событие, «Пропустить N» — N событий одним запросом. «Сбросить» возвращает сессию в начало, «Закрыть сессию» завершает её.

Выбор файла через «Обзор…» и чтение MLIR-файлов стадий обеспечивает dev-сервер Vite, поэтому **пошаговая симуляция работает только при `npm run dev`**. В собранном приложении (`npm run preview`, `dist/`) и в автономных HTML-отчётах этой функции нет.

## Генерация HTML-отчёта

Перейдите в директорию `ui` и выполните:

```bash
npm run report -- --input ../output/experiment --output ../reports/experiment.html
```

Параметры:

- `--input` (`-i`) — путь к директории эксперимента (обязательный);
- `--output` (`-o`) — путь и имя создаваемого HTML-файла (по умолчанию `report.html` в текущей директории);
- `--help` (`-h`) — краткая справка.

Перед генерацией автоматически выполняется сборка интерфейса.

Пример для демонстрационного эксперимента:

```bash
npm run report -- --input fixtures/demo --output ../reports/demo.html
```

Результатом будет файл `demo.html` с интерфейсом CacheScope и встроенными данными эксперимента. Его можно открыть непосредственно в браузере или передать другому пользователю — Vite и Node.js для просмотра не нужны. В отчёте нет выбора папки и пошаговой симуляции.

Полный сценарий compiler → simulator → UI из корня репозитория создаёт experiment bundle и вызывает этот генератор:

```bash
python3 examples/product-e2e/run.py
```

Итоговый файл — `output/product-e2e/report.html`, текстовая сводка с дельтами — `output/product-e2e/RESULTS.md`.

## Ограничения

- UI отображает уже подготовленные результаты и не запускает compiler pipeline или cache emulator.
- Для просмотра статистики необходим `statistics.json`.
- Поинструкционная статистика доступна только при наличии поля `instructions`.
- Hit rate и miss rate считаются отдельно для каждого уровня; показатели разных уровней не суммируются.
- Если trace усечён, счётчики неполные и сравнение вариантов некорректно — UI предупреждает об этом.
- UI не оценивает wall-clock performance и количество CPU cycles.
- Автономный отчёт содержит данные только одного эксперимента.
- Пошаговая симуляция требует запущенного backend и dev-сервера Vite.
