# CacheScope UI

Веб-интерфейс для просмотра и сравнения результатов моделирования работы кэш-памяти в проекте CacheScope.

UI позволяет загружать готовые эксперименты, изучать статистику работы кэша для разных вариантов программы и сравнивать результаты между собой. Также поддерживается генерация автономных HTML-отчётов, которые можно открывать и передавать без запуска веб-сервера.

При запуске полного приложения интерфейс принимает **MLIR и NPZ**, позволяет
выбрать функцию, привязать тензоры и настроить иерархию кэшей. Компиляция,
исполнение и симуляция выполняются backend, а прогресс и готовый отчёт остаются
на той же странице. Запуск из корня: `docker compose up --build`, затем
http://localhost:9055. [Готовый пример](../examples/ui-upload/README.md).

Готовый автономный отчёт уже находится в
[output/product-e2e/report.html](../output/product-e2e/report.html): скачайте
его через **Download raw file** и откройте в браузере без установки зависимостей.
[Инструкция и данные эксперимента](../output/product-e2e/README.md).

## Возможности

- **Загрузка экспериментов** — импорт готовой директории с результатами через выбор папки в браузере.
- **Общая статистика** — просмотр количества обращений, попаданий (`hits`), промахов (`misses`), вытеснений (`evictions`) и обратных записей (`writebacks`).
- **Hit rate и miss rate** — расчёт доли попаданий и промахов для каждого уровня кэша.
- **Поддержка иерархии кэшей** — просмотр статистики отдельных уровней (L1, L2 и других, если они присутствуют в данных).
- **Сравнение вариантов** — сопоставление базовой реализации и оптимизированных вариантов по основным метрикам.
- **Поинструкционная статистика** — просмотр результатов моделирования для отдельных инструкций, если соответствующие данные доступны.
- **Проверка согласованности данных** — отображение предупреждений при обнаружении противоречий в статистике или проблем с trace.
- **Экспорт отчётов** — генерация автономного HTML-файла с интерфейсом CacheScope и данными выбранного эксперимента.

## Профили процессоров и ручная конфигурация

Доступны два профиля **встроенного объединённого L1**. Внешний L2 зависит
от платы и в них не включён; межуровневой связи нет.

| Процессор и режим | Размер | Строка | Ways | Замещение | Запись | Промах записи |
|---|---|---|---|---|---|---|
| IntelDX2 | 8 KiB | 16 B | 4 | Intel tree-PLRU | write-through | no-write-allocate |
| Write-Back Enhanced IntelDX4, Enhanced Bus Mode / WB | 16 KiB | 16 B | 4 | Intel tree-PLRU | write-back | no-write-allocate |

Источники: [Intel 273021-001, §7.1–7.1.2](https://bitsavers.trailing-edge.com/components/intel/80486/273021-001_Embedded_Intel486_Processor_Family_Developers_Manual_199710.pdf#page=179),
[§7.5, рис. 7-2](https://bitsavers.trailing-edge.com/components/intel/80486/273021-001_Embedded_Intel486_Processor_Family_Developers_Manual_199710.pdf#page=186),
[табл. 7-6: промах без allocation в WB-режиме](https://bitsavers.trailing-edge.com/components/intel/80486/273021-001_Embedded_Intel486_Processor_Family_Developers_Manual_199710.pdf#page=194).
Ссылки для каждого параметра, условия выбранного режима и причины исключения
прежних профилей — в [проверке профилей](../docs/PROCESSOR_PRESET_AUDIT.md).
Те же источники доступны под выбором процессора в UI.

Профили задают кэшируемую память при включённом кэше; DX4 — private-линии E/M
при WB/WT#=1, PWT=0. Трасса учитывает данные, без выборки команд, snoop и
тайминга шин. Это модель встроенного L1 указанного процессора в выбранном режиме.

Все поля можно менять вручную. Правка снимает выбор профиля; повторный выбор
восстанавливает его настройки. `PLRU4` реализует дерево Intel и требует ровно
четыре ways; при выборе этой политики UI устанавливает ways=4.

Ручные настройки:

- capacity, строка, ways; LRU/FIFO/Random/PLRU4 и seed для Random;
- write-back / write-through и write-allocate / no-write-allocate для каждого уровня;
- exclusive / inclusive / NINE для каждой соседней пары;
- передача чистых вытеснений вниз; для exclusive она обязательна;
- NINE: заполнение нижних уровней при demand fetch либо только при вытеснении.

Конфигурация сохраняется в эксперименте и восстанавливается после reload.
Старый `cache_profile` удалённого профиля не возвращает процессор в список:
его фактические `levels` и `hierarchy` загружаются как ручные настройки.

Отчёт показывает политики, локальные hit rates, back invalidations и memory
reads/writes/write bytes/writebacks. Старые отчёты по-прежнему загружаются;
отсутствующие новые счётчики показаны как «—». Финальный flush не выполняется.
Полная семантика — в [описании моделей](../docs/CACHE_MODELS.md#политики-записи-и-иерархии).

## Входные данные

Для импорта готового эксперимента UI работает с результатами, подготовленными
другими компонентами CacheScope. Для загрузки программы используется отдельный
[API экспериментов](../docs/EXPERIMENT_API.md); browser не исполняет MLIR сам.

Ожидаемая структура директории эксперимента:

```text
output/<experiment>/
├── summary.json
├── baseline/
│   └── trace.json
├── tile4/
│   └── trace.json
├── tile4-ikj/
│   └── trace.json
└── simulation/
    ├── baseline-l1/
    │   └── statistics.json
    ├── tile4-l1/
    │   └── statistics.json
    └── tile4-ikj-l1/
        └── statistics.json
```

Основные источники данных:

- `trace.json` — trace, сформированный compiler trace producer.
- `statistics.json` — результаты симуляции, сформированные cache emulator.
- `events.json` — подробные результаты по отдельным обращениям; для основной страницы статистики не требуется.

Поддерживаемые схемы:

- `cachescope.trace.v1`;
- `cachescope.simulation-statistics.v1`.

UI проверяет соответствие схемам и использует доступные расширения формата. Отсутствующие необязательные данные отображаются как недоступные, а не как нулевые значения.

## Запуск в режиме разработки

Требуется Node.js `^20.19.0` или `>=22.12.0` и npm.

```bash
cd ui
npm ci
npm run dev
```

После запуска Vite выведет адрес локального сервера в терминале. Этот режим предназначен для разработки и интерактивного просмотра экспериментов.

## Генерация HTML-отчёта

CacheScope позволяет создать автономный HTML-файл с тем же интерфейсом, который используется в веб-версии.

Перейдите в директорию `ui` и выполните:

```bash
npm run report -- --input ../output/experiment --output ../reports/experiment.html
```

Параметры:

- `--input` (`-i`) — путь к директории эксперимента.
- `--output` (`-o`) — путь и имя создаваемого HTML-файла.

Перед генерацией отчёта автоматически выполняется сборка интерфейса.

Например, для демонстрационного эксперимента:

```bash
npm run report -- --input fixtures/demo --output ../reports/demo.html
```

Результатом будет файл `demo.html`, содержащий интерфейс CacheScope и встроенные данные эксперимента.

Полный compiler → simulator → UI сценарий из корня репозитория сам создаёт
реальный experiment bundle и вызывает этот генератор:

```bash
python3 examples/product-e2e/run.py
```

Итоговый файл находится в `output/product-e2e/report.html`, текстовая сводка с
дельтами — в `output/product-e2e/RESULTS.md`.

Отчёт можно открыть непосредственно в браузере или передать другому пользователю. Для его просмотра не требуется запускать Vite или устанавливать Node.js.

## Ограничения

- Загрузка программы поддерживает статические identity-layout memref<f32> аргументы, без возвращаемых значений; NPZ содержит float32 массивы соответствующей формы.
- Для просмотра статистики необходим `statistics.json`.
- Поинструкционная статистика доступна только при наличии поля `instructions`.
- Детальная визуализация отдельных событий trace и `events.json` не является частью текущей версии.
- Hit rate и miss rate рассчитываются отдельно для каждого уровня. Показатели разных уровней не суммируются.
- UI не оценивает wall-clock performance и количество CPU cycles по trace или статистике симуляции.
- Автономный отчёт содержит данные только одного выбранного эксперимента.

## Статус

Первая версия интерфейса (v0.1).

Реализованы импорт экспериментов, просмотр статистики, поддержка иерархии кэшей, сравнение вариантов и генерация автономных HTML-отчётов. Форматы входных данных определяются общими контрактами проекта CacheScope.

Браузерный E2E с настоящим backend: `npm run test:e2e`; предварительно
поднимите приложение и установите Chromium через `npx playwright install chromium`.
Полный сценарий и негативные проверки запускаются workflow `UI experiment E2E`.
