# Trace runner

C++17-библиотека воспроизводит полный `cachescope.trace.v1` через переданный
`ICacheSimulator`. Модель сама реализует иерархию, деление на строки и cache
policies. Раннер собирает статистику и последовательно пишет JSON-отчёт.

## Сборка без LLVM

Из корня репозитория:

```bash
cmake -S runner -B build/runner -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/runner
ctest --test-dir build/runner --output-on-failure
```

CMake скачивает nlohmann/json 3.12.0 с проверкой SHA-256. Для сборки без сети
можно передать `-DFETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON=/path/to/json-3.12.0`.
Библиотеку можно подключить через `add_subdirectory(path/to/runner runner-build)`
и `target_link_libraries(your_target PRIVATE CacheScope::Runner)`.

## API

```cpp
#include <cache_simulator/trace_runner.hpp>

cache_simulator::RunSummary replay(cache_simulator::ICacheSimulator &model) {
  return cache_simulator::run_trace("trace.json", model, "statistics.json");
}
```

`level_names()` модели возвращает названия от L1 наружу. Каждый
`LineAccessResult.level` — номер в этом списке, начиная с 1. В `lines` модель
возвращает проверки строк на всех реально посещённых уровнях для исходного
запроса; внутренние writeback/fill обращения исключаются. Непосещённые уровни
не добавляются. Каждый непустой запрос должен содержать проверки первого уровня.

Раннер сначала проверяет весь файл и собирает диапазоны смещений массивов.
Затем назначает адреса, вызывает `clear()` и вторым проходом вызывает
`read/write`. Файл должен оставаться неизменным на протяжении обоих проходов.
Память зависит от числа массивов, статических инструкций, уровней и размера
одного события/результата модели, а не числа динамических событий. Ограничения
на число событий нет; адреса и счётчики имеют разрядность `uint64_t`.

Авторазмещение идёт по возрастанию `memref_id` от адреса `0x10000000`. Логическая
база каждого массива выравнивается на 64 байта. Резервируется наблюдаемый диапазон
с включением смещения 0; отрицательные смещения сохраняются. Выбирается минимальная
база без пересечения с предыдущим диапазоном. Размещение влияет на конфликты
кеша и сохраняется в отчёте. При сравнении экспериментов следует проверять,
что их размещения совпадают.

Поддержаны `memref_offset` и `read/write`. `process_address`, `read_write`,
обрезанные и некорректные трассы отклоняются с `std::runtime_error` до
`clear/read/write`. Проверяются schema, обязательные поля, целочисленные типы,
статическая таблица accesses, последовательные sequence от 0, размеры и
переполнение адресов. Неизвестные дополнительные поля допускаются.

Отчёт создаётся во временном файле рядом с назначением и заменяет предыдущий
только после успешного прогона, записи и закрытия. Ошибка модели/I/O сохраняет
предыдущий отчёт; состояние модели после ошибки исполнения не определено.
Каталог назначения создаётся автоматически. Модель и потоки одного запуска
не должны одновременно использоваться другим кодом.

Формат результата и пример для UI: [statistics contract](../docs/STATISTICS_FORMAT.md).

## Тесты

- `cachescope.runner-integration`: известные результаты трёх уровней, частичные
  попадания, чтения/записи, инструкции, адреса и повторяемость;
- `cachescope.runner-validation`: некорректные данные и ответы модели, ошибки
  исполнения/I/O и сохранение старого отчёта;
- `cachescope.runner-random-miss`: 1000 обращений через `RandomMissCache`,
  независимый miss с вероятностью 50%, seed 42; сверка отчёта с выданными
  исходами без требования ровно 50% в выборке;
- `cachescope.runner-streaming`: 1 000 001 событие, потоковые вход и выход без
  ограничения производителя в 1 000 000 событий.

Smoke-тест сохраняет вход в `build/runner/smoke/trace.json`, а полный отчёт
в `build/runner/smoke/statistics.json`. Для другого каталога сборки файлы
сохраняются в его подкаталоге `smoke/`. При следующем успешном запуске отчёт
заменяется.

Для smoke-теста отдельно:

```bash
ctest --test-dir build/runner -R random-miss --output-on-failure
```
